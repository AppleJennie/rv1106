## 1. 项目是什么

基于 **LuckFox Pico RV1106**（单核 Cortex-A7 + NPU，uClibc）的驾驶员疲劳监测系统（DMS）。

```text
MIS5001 摄像头 → ISP → VI(NV12 dma-buf)
                    ├→ VENC → JPEG → MJPEG 推流（ffplay/浏览器观看）
                    └→ RGA → RetinaFace(NPU) → 106点landmark(NPU)
                          → EAR/MAR/低头特征 → 疲劳状态机
                          → status.json / 调试流 / 状态截图
```

可检测状态：`NORMAL / EYE_CLOSED / LONG_EYE_CLOSED / YAWN / HEAD_DOWN / NO_FACE`。

板端程序路径 `/root/hand_capture_right`，模型在 `/mnt/sdcard/dms/models/`，日志 `/mnt/sdcard/dms/live/console.log`。

## 2. 快速上手

### 2.1 交叉编译

```bash
cd build
cmake ..          # 首次或改了 CMakeLists 时
make -j$(nproc)
```

产物：`build/hand_capture_right`。SDK 路径在 `CMakeLists.txt` 顶部（`MPP_DIR=/home/jennie/hhh/luckfox-pico/media/out` 等），换机器先改这里。

### 2.2 部署运行

```bash
./scripts/deploy_dms.sh     # 一键：推二进制+模型+启动+adb forward 8090
```

或手动（模型已在板上时只需推二进制）：

```bash
adb push build/hand_capture_right /root/hand_capture_right
adb shell "killall -9 hand_capture_right; /root/start_hand_capture.sh"
adb forward tcp:8090 tcp:8090
```

### 2.3 观看与状态

```bash
ffplay -fflags nobuffer -framedrop http://127.0.0.1:8090/stream.mjpg        # 原始流
ffplay ... http://127.0.0.1:8090/stream_debug.mjpg                          # 调试流（绿框+106点+HUD）
curl http://127.0.0.1:8090/status.json                                      # 状态 JSON
```

注意：**打开调试流时 AI 会降到 ~2.5FPS**（debug 流是 CPU 软解软编，留给 V2-C 用硬件 OSD 解决）；关掉即恢复 15FPS。

## 4. 关键开关（`include/common.h`）

| 宏 | 默认 | 作用 |
|----|------|------|
| `APP_MODE_DMS` | 1 | DMS 模式（=0 为原始采集模式） |
| `DMS_HW_PREPROCESS` | 1 | RGA 硬件预处理；**=0 完整回退软件路径**（A/B 对比用） |
| `DMS_ENABLE_LANDMARK_106` | 1（部署版） | 106 点推理总开关 |
| `DMS_ENABLE_HEADPOSE` | 0 | headpose 模型（未启用） |
| `DMS_FEATURE_EMA_ALPHA` | 0.65 | EMA 平滑系数 |
| `DMS_EAR_SANE_MAX` | 0.60 | 单眼 EAR 物理上限，超过判关键点退化 |

疲劳阈值参数（同文件）：`DMS_EAR_CLOSE_RATIO 0.72 / RECOVER 0.85`、`DMS_MAR_YAWN_RATIO 1.6 / RECOVER 1.2`、`DMS_EYE_CLOSED_MS 800`、`DMS_LONG_EYE_CLOSED_MS 1500`、`DMS_YAWN_MS 1000`、`DMS_HEAD_DOWN_MS 1500`。

## 6. 已知问题与风险（按优先级）

1. **USB 供电不稳**：高负载时板子掉电重启过 2 次。上车/长期运行前必须解决（独立 5V 或优质线材+后置 USB 口）。
2. **程序无开机自启/看门狗**：重启后需手动启动。车规场景必须补：S99 自启脚本 + 软硬件看门狗。
3. **微笑可误判为哈欠**：MAR 一维特征区分不了。已构思方案（内唇开度+嘴宽约束），待实施。原始数据在 `acceptance/` 各 CSV。
4. **扭头时闭眼判定不可信**：106 点在侧脸退化（单眼塌 0/冲 1）。已有 fmax+0.6 上限过滤兜底，根治方案是加头部姿态门槛（超 ±25° 挂起判定），待实施。
5. **106 点模型校准集是随机图**：模拟器误差 <1px 不代表真实精度。正式部署前用 100~200 张真实人脸 crop 重校准（`tools/convert_landmark_rknn.py --calib-dir`）。
6. **License**：2d106det 来自 InsightFace，**仅限非商业研究**。商用需换自训模型（PFLD/PIPNet）或取得授权。
7. **调试流拖慢 AI**（见 2.3），V2-C 用硬件 OSD 解决。
8. `camera_restart()` 后 RGA MB pool 失效 → 自锁回退软件路径；如需保持加速要重建 RGA 模块。
