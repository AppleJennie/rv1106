# Hand Capture Right —— 发送端通讯接口文档

## 一、协议概述

| 项目 | 说明 |
|------|------|
| 传输层 | TCP |
| 默认端口 | 9000 |
| 服务端 IP | `UPLOAD_SERVER_IP`（默认 192.168.4.17） |
| 连接超时 | 5 秒 |
| 发送/接收超时 | 5 秒 |
| 消息编码 | ASCII 文本头 + 二进制文件体 |

---

## 二、连接建立

发送端主动连接接收端：

```c
socket(AF_INET, SOCK_STREAM, 0)
connect(server_ip, 9000)
```

连接成功后，保持长连接，按顺序发送多个文件。

## 三、报文格式

### 3.1 文件发送请求头

发送方向接收方发送文本行（以 `\n` 结尾）：

```
FILE <相对路径> <文件大小>\n
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `FILE` | 字符串 | 固定命令字 |
| `相对路径` | 字符串 | 不允许空格。示例：`code/2026-05-30_14-25-36.csv` |
| `文件大小` | 十进制整数 | 单位：字节。范围：0 ~ 200MB |

**示例：**
```
FILE code/2026-05-30_14-25-36.csv 1234\n
FILE code/2026-05-30_14-25-36_enc.csv 5678\n
FILE photo/2026-05-30_14-25-36/001.jpg 45023\n
```

### 3.2 文件内容传输

请求头发送完成后，发送方立即发送**原始二进制文件内容**，长度必须严格等于请求头中的 `文件大小`。

接收方按指定字节数读取，不依赖边界符。

### 3.3 接收确认

文件内容接收完毕后，接收方向发送方返回：

| 响应 | 含义 | 发送方行为 |
|------|------|-----------|
| `OK\n` | 接收成功，已落盘 | 继续发送下一个文件 |
| `ERR\n` | 接收失败（空间不足/路径非法/写入失败等） | 中断上传，回滚当前组状态 |

**注意：** 发送方在发送完文件内容后，必须等待接收方返回 `OK\n` 或 `ERR\n`，才能发送下一个文件。

## 四、上传流程（按组）

发送端以**组**为单位上传，每组对应一秒的数据：

```
组名 = 时间戳，如：2026-05-30_14-25-36
```

### 4.1 单组上传顺序

```
1. FILE code/<组名>.csv           <大小>\n  → 发送 .csv 内容  → 等待 OK
2. FILE code/<组名>_enc.csv       <大小>\n  → 发送 _enc.csv  → 等待 OK
3. FILE photo/<组名>/001.jpg      <大小>\n  → 发送 001.jpg   → 等待 OK
4. FILE photo/<组名>/002.jpg      <大小>\n  → 发送 002.jpg   → 等待 OK
   ...（按文件名排序，依次发送）
```

**约束：**
- `_enc.csv` 必须存在，否则该组上传直接失败回滚
- 照片按 `001.jpg ~ 030.jpg` 排序发送

### 4.2 状态流转

```
采集完成：
  code/<组名>.ready        ← 就绪标记
  code/<组名>.csv
  code/<组名>_enc.csv
  photo/<组名>/*.jpg

开始上传：
  code/<组名>.uploading    ← ready 重命名为 uploading

上传成功：
  code/<组名>.uploaded     ← 上传完成标记
  （同时删除 .uploading 和 .ready）

上传失败/取消：
  code/<组名>.ready        ← uploading 回滚为 ready
```

## 五、发送端 C 接口

### 5.1 头文件

```c
#include "net_transfer.h"
```

### 5.2 接口函数

```c
/* 初始化上传模块（当前为空实现，保留扩展） */
bool upload_init(void);

/* 释放上传模块资源（关闭 socket） */
void upload_deinit(void);

/*
 * 上传所有待上传的会话组。
 * base_path: SD 卡根目录，如 "/mnt/sdcard/right"
 * cancel_flag: 取消标志指针，外部设置为 1 可中断上传
 *
 * 返回：true = 全部上传成功；false = 上传失败或被取消
 */
bool upload_all_sessions(const char *base_path, volatile int *cancel_flag);

/* 请求取消当前上传 */
void upload_request_cancel(void);

/* 查询待上传组数量 */
int upload_count_pending(const char *base_path);
```

### 5.3 使用示例

```c
volatile int cancel = 0;

// 开始上传
if (!upload_all_sessions("/mnt/sdcard/right", &cancel)) {
    printf("上传失败\n");
}

// 取消上传
cancel = 1;
upload_request_cancel();
```

## 六、路径安全规则

接收端对 `相对路径` 执行以下校验，**不满足则直接返回 ERR：**

| 规则 | 拒绝示例 |
|------|---------|
| 禁止绝对路径 | `/etc/passwd` |
| 禁止 `..` 遍历 | `../etc/passwd` |
| 禁止反斜杠 | `code\test.csv` |
| 只允许 `code/` 和 `photo/` 开头 | `tmp/test.csv` |

合法路径示例：
```
code/2026-05-30_14-25-36.csv
code/2026-05-30_14-25-36_enc.csv
photo/2026-05-30_14-25-36/001.jpg
```

## 七、错误处理

| 错误场景 | 发送端行为 | 接收端响应 |
|---------|-----------|-----------|
| 连接失败 | 重试 3 次，间隔 1 秒 | — |
| 发送文件头失败 | 关闭连接，标记上传失败 | — |
| 发送文件内容失败 | 关闭连接，标记上传失败 | — |
| 等待 OK 超时 | 关闭连接，标记上传失败 | — |
| 接收非 OK/ERR | 关闭连接，标记上传失败 | — |
| 接收端空间不足 | — | `ERR\n` |
| 路径非法 | — | `ERR\n` |
| `_enc.csv` 缺失 | 不上传该组，回滚 ready | — |
