# Hand Capture Right 使用说明书

## 一、产品概述

**Hand Capture Right** 是专为 LuckFox Pico RV1106 设计的右手数据采集系统，用于同步采集：

- **照片**：1920×1536 @ 30FPS JPEG
- **编码器**：3 路 MT6701 磁编码器 @ 90Hz
- **时间戳**：真实系统时间（依赖 RTC）

采集数据按秒分组存储到 SD 卡，支持一键上传到服务器。

---

## 二、硬件要求

| 项目 | 规格 |
|------|------|
| 主控 | LuckFox Pico RV1106 |
| 摄像头 | RKMPI 兼容摄像头 |
| 编码器 | 3× MT6701（I2C 地址 0x06）+ TCA9548A 切换器 |
| SD 卡 | Class 10 以上，建议 64GB+ |
| 蜂鸣器 | GPIO1_D3（GPIO59） |
| 按键 | 录制键 GPIO0、上传键 GPIO1 |
| LED | 系统灯 + 状态灯（SPI 驱动） |

### 接线确认

```
I2C-3 总线：
  SDA/SCL → TCA9548A (0x70)
  CH1/2/3 → 3 个 MT6701 (0x06)

GPIO：
  GPIO0 → 录制按键
  GPIO1 → 上传按键
  GPIO59 → 蜂鸣器
```

## 三、安装部署

### 1. 交叉编译

```bash
cd build
cmake ..
make -j$(nproc)
```

### 2. 上传到板子

```bash
adb push hand_capture_right /root/
adb shell chmod +x /root/hand_capture_right
```

### 3. 自启动配置

确保 RTC 同步脚本早于采集程序启动：

```bash
mv /etc/init.d/S99rtcinit /etc/init.d/S90rtcinit
chmod +x /etc/init.d/S90rtcinit
```

采集程序保持：
```bash
/etc/init.d/S99hand_capture
```

### 4. 首次设置 RTC

```bash
date -s "2026-05-30 22:30:00"
hwclock -w -f /dev/rtc0
hwclock -r -f /dev/rtc0
```

## 四、LED 状态说明

| 系统灯（第一个） | 状态灯（第二个） | 含义 |
|-----------------|-----------------|------|
| 黄色闪烁 | 熄灭 | 初始化/预热中 |
| 绿色常亮 | 熄灭 | 待机（READY） |
| 绿色闪烁 | 熄灭 | 采集中（RECORDING） |
| 绿色常亮 | 蓝色闪烁 | 上传中（UPLOADING） |
| 绿色常亮 | 红色常亮 | 上传失败（UPLOAD_FAIL） |
| 红色常亮 | 红色常亮 | 错误（ERROR） |

## 五、操作说明

### 录制按键（GPIO0）——点按切换

| 当前状态 | 按键动作 | 结果 |
|---------|---------|------|
| READY / UPLOAD_FAIL | 点按一下 | 开始采集 |
| RECORDING | 点按一下 | 停止采集 |

### 上传按键（GPIO1）——点按切换

| 当前状态 | 按键动作 | 结果 |
|---------|---------|------|
| READY / UPLOAD_FAIL | 点按一下 | 开始上传 |
| UPLOADING | 点按一下 | 取消上传 |

### 蜂鸣器

| 场景 | 行为 |
|------|------|
| SD 卡剩余空间 < 4GB | 连续短促响 10 次（100ms ON / 100ms OFF） |

## 六、SD 卡文件结构

采集完成后，SD 卡 `/mnt/sdcard/right/` 下：

```
right/
├── code/
│   ├── 2026-05-30_14-25-36.csv          # 照片索引
│   ├── 2026-05-30_14-25-36_enc.csv      # 编码器数据
│   └── 2026-05-30_14-25-36.ready        # 就绪标记
├── photo/
│   └── 2026-05-30_14-25-36/
│       ├── 001.jpg
│       ├── 002.jpg
│       └── ...
```

### 照片 CSV 格式

```csv
index,frame_id,img_timestamp_us,img_name
1,1,174029851,001.jpg
2,2,174063184,002.jpg
```

### 编码器 CSV 格式

```csv
index,enc_frame_id,timestamp_us,enc1,enc2,enc3,valid1,valid2,valid3
1,1,123456789,12.300,-1.000,88.200,1,0,1
2,2,123467890,12.350,45.100,88.250,1,1,1
```

- `enc1/2/3`：角度值，失败时为 `-1.000`
- `valid1/2/3`：`1`=有效，`0`=读取失败
- 每秒一个文件，目标约 90 行

## 七、编码器配置

`include/common.h`：

```c
#define ENC_ACTIVE_MASK         0x07    // 0x01|0x02|0x04，三路全开
```

如果只接了一路，临时改为：
```c
#define ENC_ACTIVE_MASK         0x01    // 只开编码器1
```

## 八、常见问题

### Q1：文件名显示为 1970-01-01
**原因**：RTC 未同步或系统时间未设置。  
**解决**：执行 `hwclock -s -f /dev/rtc0`，确保 `S90rtcinit` 在采集程序之前启动。

### Q2：编码器 CSV 里某路全是 -1
**原因**：该路编码器未接线或 I2C 通信失败。  
**解决**：检查该路 MT6701 接线，确认 TCA9548A 对应通道正常。

### Q3：照片出现 0KB
**解决**：已改为 tmp+rename 写入，正式照片不会 0KB。异常退出可能残留 `.tmp` 文件，启动时会自动清理。

### Q4：蜂鸣器不响
**原因**：当前阈值是 SD 卡剩余 < 4GB。  
**测试**：临时改 `STORAGE_FREE_WARN_THRESHOLD_MB` 为大于当前剩余空间的值。

### Q5：上传失败
**检查**：
1. 接收端服务器 IP/端口是否正确（默认 192.168.4.17:9000）
2. 网络是否可达：`ping 192.168.4.17`
3. 接收端是否运行：`./receive_server`
4. 上传组是否有 `.ready` 标记

## 九、接收端部署

在接收服务器上：

```bash
cd receive_server
make
./receive_server
```
